## 3D 工具 usdc 二进制 USDZ 支持：集成 tinyusdz WASM 解析器
- 问题：用户反馈「usdz 不生效」——诊断显示是二进制 usdc（crate），但用户需要的是**直接加载**，不是报错。
- 根因：three.js 官方 USDZLoader 仅支持 zip 内嵌 ASCII usda，真实世界（Apple / Reality Converter / Blender 默认导出）的 USDZ 几乎全是二进制 usdc。之前 UX 增强只做了诊断提示，没有解决加载问题。
- 方案：集成 **tinyusdz**（浏览器端唯一成熟的 usdc 解析器，WASM 核心 zstd 压缩后 1.3MB）作为 usdc 分支的懒加载解析器。ASCII usda 继续走 three.js 内置 USDZLoader（轻量、无需 WASM），usdc 才触发 WASM 下载。
- 自托管文件（全部放在 `assets/tools/3d-viewer/lib/tinyusdz/`）：
  - `TinyUSDZLoader.js`（138KB）、`TinyUSDZLoaderUtils.js`（123KB）、`usdzconvert.js`（111KB）、`TinyUSDZMaterialX.js`（141KB）、`EXRDecoder.js`（7.8KB）、`TypedArrayOwnership.js`（1.5KB）
  - `tinyusdz.js`（84KB JS glue）、`tinyusdz.wasm.zst`（1.3MB zstd 压缩 WASM）
  - `fzstd.mjs`（24KB，zstd 解压器，importmap 映射）
  - `addons/loaders/HDRLoader.js`（shim，代理到本地 `RGBELoader.js`，解决 three 0.160 改名）
- 加载管线：
  1. 文件拖入 → `USDZLoader.parse()`（three.js 内置）
  2. 若 meshCount === 0 → `diagnoseUsdz()` 检查首条目格式
  3. 若 `crate === true` → 状态栏提示「检测到二进制 usdc，正在加载 WASM 解析器…」
  4. 首次触发时动态 import `TinyUSDZLoader.js` + `TinyUSDZLoaderUtils.js`，`init({ useZstdCompressedWasm: true })`
  5. `loader.loadAsync(blobUrl)` → `buildThreeNode(usdRoot, defaultMtl, usdScene)` → 返回 Three.js Object3D
- 验证结果：
  - 官方 usd-core 写入器生成的 usdc USDZ（环面 + 棋盘格 PNG 贴图 + UsdPreviewSurface 材质，2.3k 三角面 / 1.2k 顶点）：加载成功，状态栏正确显示面数/顶点数，UV 坐标保留，无 JS 报错。
  - 内置示例（TorusKnot）回归：提示层隐藏，状态正常。
  - 无 UV STL 回归：提示层显示，点击「生成投影 UV」后隐藏，UV 棋盘格出现。
  - usdc 假 USDZ（之前 UX 增强的测试文件）：已删除，不再验证。
- 依赖管理：
  - `tools/3d-viewer.md` importmap 新增 `three/examples/jsm/` → `lib/addons/` 和 `fzstd` → `lib/tinyusdz/fzstd.mjs`。
  - `TinyUSDZLoaderUtils.js` 依赖 `three/examples/jsm/loaders/HDRLoader.js`（three 0.160 已改名 RGBELoader），本地 shim 代理解决。
  - `three` 依赖版本：tinyusdz rc 要求 `>=0.178.0`，但当前本地托管为 0.160.1；实际测试中 `HDRLoader` shim + `EXRLoader` + `MeshPhysicalMaterial` + `SRGBColorSpace` 均兼容，未触发版本不匹配报错。若后续遇到 API 变更，需升级本地 three.js 或降级 tinyusdz。

## 3D 工具 zip 模型包加载（模型站下载的 glTF / FBX / OBJ）
- 问题：用户反馈「glTF 格式和 FBX 下载的时候都是 zip 怎么办」「obj 格式也可能是 zip」。模型站（Sketchfab / CGTrader 等）的 glTF / FBX / OBJ 下载包通常把主模型 + `.bin` / `.mtl` / 贴图一起压缩成 zip，工具原来只认裸模型文件，zip 直接被拒。
- 方案：在 `loadFiles` 中增加 `.zip` 分支，解包后用 `LoadingManager.setURLModifier` 重写资源引用，实现拖 zip 直接加载。
- 核心实现 `loadZipModel(buffer, zipName)`：
  1. `fflate.unzipSync` 解压全部条目到内存；过滤 `__MACOSX/`、隐藏文件（`.DS_Store` 等）和目录占位。
  2. 选主模型文件优先级：`.glb` / `.usdz` > `.gltf` > `.fbx` > `.obj` > `.usdc` / `.usda` > `.stl`；同一扩展名多个候选时取**路径最短**的（根目录主模型优先，避免误选零件分文件）。OBJ 多 MTL 匹配：同名 > 同目录 > 任意。
  3. 为每个条目创建 `blob:` URL；保存到模块级 `zipBlobUrls` 数组，下次加载新模型时先 `revokeObjectURL` 释放上一批，避免内存累积。
  4. `LoadingManager.setURLModifier` 拦截资源路径：依次尝试「精确路径」「目录后缀匹配（`model/textures/tex.png` → `tex.png`）」「文件名兜底（大小写不敏感）」，兼容 glTF `.bin`/贴图、FBX 反斜杠绝对路径、MTL `map_Kd` 等。
  5. 按主模型扩展名走各 Loader（`GLTFLoader` / `FBXLoader` / `OBJLoader`+`MTLLoader` / `STLLoader` / `USDZLoader`+tinyusdz），**传入同一个带 URL 重写的 `LoadingManager`**。
- 验证结果：
  - glTF zip（手工构造：主模型在子目录、外部 `.bin`、贴图再套一层 `textures/`、含 `__MACOSX` 和 `.DS_Store` 垃圾条目）：加载成功，状态栏 `scene — 0.0k 三角面 / 0.0k 顶点`，无报错。
  - FBX zip（three.js 官方示例 `Samba Dancing.fbx`，3.6MB，带 `__MACOSX` 垃圾）：加载成功，状态栏 `Samba Dancing — 55.3k 三角面 / 166.0k 顶点`，线框/UV/PBR/法线四视口全部正常渲染。
  - OBJ zip（`model.obj` + `model.mtl` 引用 `tex.png`、贴图实际藏在 `assets/images/` 深层目录测文件名兜底、含干扰零件 `parts/spare_part_0001.obj`）：加载成功选中主模型而非干扰件、零 console 报错、贴图经 blob URL 解码成功（HTMLImageElement.src 探针确认 `ok: true`）。MTLLoader 的贴图加载确认走 `setManager(this.manager)` → `loadTexture` 同一 manager，URL 重写拦截生效。
  - 内置示例回归：刷新后自动加载环面纽结（15.8k 三角面 / 8.2k 顶点），无报错。
  - 验证技巧：无 console 命令时，用 eval 预装探针 —— 覆写 `console.error/warn` 收集日志、`Object.defineProperty(HTMLImageElement.prototype, 'src')` 记录贴图加载（src + load 事件 naturalWidth）。
- 改动文件：
  - `assets/tools/3d-viewer/app.js`：加入 `loadZipModel` / `u8Buffer` / `zipBlobUrls`，扩展文件识别正则和错误提示。
  - `tools/3d-viewer.md`：accept 属性增加 `.zip`；说明文案增加 zip 支持描述。
